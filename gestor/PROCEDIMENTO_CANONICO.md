# Gestor Autônomo da Lojinha — procedimento canônico v1.0
Atualizado em 2026-10-29. Este arquivo documenta a rotina do executor no NOTE-MAGNOBENH. Não é autorização para ignorar validações. O plugin deve executar operações reais via Remote Desktop Commander, sem improvisar outros navegadores.

## Regra principal
Após escolher uma oferta com ID individual verificado, usar SOMENTE o executor C:\Users\magno\lojinha_executor.ps1 com RunId persistente. Manter primeira aba no anúncio do Mercado Livre e segunda aba no editor da lojinha, ambas na MESMA janela dedicada do Chrome autenticado. Nunca depender do histórico do chat para recordar a sequência.

## Fluxo
1. Validar oferta individual: IDs MLB###### do próprio anúncio (não ID /p/ do catálogo). Criar offers_raw.json, validar com validate-offers; gravar selected_index.txt, executar select-offer.
2. Executar open-product-by-id: URL https://produto.mercadolivre.com.br/MLB-<dígitos>. A ação já cria a segunda aba de editor. Confirmar HWND e que é janela própria, sem tocar nas pessoais.
3. Diagnosticar display real com lojinha_localizar_monitores.ps1; NÃO supor monitor 1 ou monitor 2. Confirmar HWND e URL real via UI Automation Document/ValuePattern, além do ID individual e da segunda aba Editor | Lojinha Magno Garcia. O título da aba pode começar com 'Uso da memória em' e nem sempre contém 'MercadoLivre'. Título isolado não prova URL.
4. Localizar a faixa de Afiliados pela hierarquia UIA. O botão físico de link pode expor o Nome UIA 'Compartilhar' OU 'Link do produto', mesmo que o texto visível diga 'Compartilhar'. Não confundir com 'Compartilhar' comum da página. Selecionar controle Button dentro de grupo Afiliados, na área visível, vinculado ao HWND, conferindo tela/retângulo e centro dentro do monitor. Não aceitar apenas nome fixo ou coordenadas fixas.
5. Primeiro validar: powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Users\magno\lojinha_validar_janela_afiliados.ps1 -RunId <id>; depois dry-run de lojinha_clique_humano_vinculado.ps1 -RunId <id> -DryRun. Se ambos aprovados, executar click-share do executor com apenas UM clique físico. Executar generate-link e exigir AFFILIATE_LINK_VISIBLE=https://meli.la/... real. Nunca inventar afiliado.
6. Com link confirmado: copy-offer, OK, open-editor, add-offer, fill-offer, OK, extract, confirm. Validar campos e preservar URL do anúncio individual; o bookmark pode trocar pelo catálogo, corrigir e verificar. Título de pesquisa pode diferir do título real; não bloquear sem conferir identidade, ID, variante e preço.
7. Categoria escolhida: selecionar existente ou criar a categoria explicitamente indicada, não trocar silenciosamente. save-offer uma vez, save-store uma vez. Conferir no GitHub data/produtos.json tanto o ID quanto o link afiliado; conferir GitHub Pages separadamente (pode haver atraso de publicação).
8. Se o anúncio está pausado, ID faltando, link indisponível ou erro real comprovado: recovery-fail, buscar outras TRÊS ofertas reais equivalentes com IDs individuais não repetidos, registrar recovery_candidates.json; recovery-prepare; mostrar opções e esperar escolha COMERCIAL; recovery-choose e retomar. Repetir enquanto houver anúncios. Não rejeitar anúncio se a falha foi apenas monitor, foco, aba, nomenclatura UIA ou janela reaproveitável; recuperar esses erros técnicos primeiro. Nunca trocar de oferta sem escolha do usuário.
9. Registar RunId, item, erro, categoria, checkpoint e IDs rejeitados de modo persistente. Não dar sucesso sem evidência de GitHub/publicação. Não reiniciar tarefa após mudança de chat.
## Caso de regressão documentado
Pedal Vintage Overdrive — MLB5468359060. Em 2026-10-29, HWND 6621614 no DISPLAY2, duas abas; URL verificada diretamente, faixa Afiliados presente. O nome UIA mudou entre 'Link do produto' e 'Compartilhar', mas o controle correto estava dentro de Afiliados. Após filtragem por HWND + hierarquia + posição, dry-run TARGET_VERIFIED HWND=6621614 X=4340 Y=160; generate-link retornou https://meli.la/2BzRFFr; GitHub main/data/produtos.json passou a conter ID e afiliado. A ausência do botão era falso negativo do localizador, NÃO indisponibilidade do anúncio.
## Proteção
O repositório é público: jamais colocar cookies, tokens, senhas, dados privados, estado de sessão ou segredos neste arquivo. O carregador do notebook deve manter cópia local conhecida e exigir validação do formato e da versão.

## Geometria dos monitores — NOTE-MAGNOBENH (verificado em 2026-10-29)
- DISPLAY1 (principal): origem X=0, Y=0; largura=1536, altura=864 pixels. Limites X=[0,1536), Y=[0,864).
- DISPLAY2: origem X=1920, Y=-39; largura=1920, altura=1080 pixels. Limites X=[1920,3840), Y=[-39,1041). O segundo monitor possui resolução e deslocamento vertical diferentes.
- Antes de cada clique, ler novamente `System.Windows.Forms.Screen.AllScreens`, obter `Bounds` e confirmar HWND, retângulo da janela e monitor que contém o ponto-alvo. Essas coordenadas são referência de configuração, NÃO devem substituir a detecção dinâmica.
- Para o botão de afiliado, usar UI Automation para encontrar o grupo `Afiliados` e o controle Button dentro dele com nome `Compartilhar` ou `Link do produto`; conferir Bounds e clicar no centro efetivamente informado. Se o ponto não estiver nos limites do monitor identificado, NÃO clicar: recalcular geometria/escala e recuperar foco. Não confundir com o botão de compartilhamento comum do anúncio.
- Nota sobre DPI/zoom: UI Automation pode retornar coordenadas em escala distinta das coordenadas físicas do Windows quando houver escalonamento; detectar DPI awareness, janela e limites reais antes de clicar. O último teste abriu `Gerar link / ID de produto` e copiou `https://meli.la/2BzRFFr`, confirmado pelo usuário como pertencente ao pedal escolhido.
